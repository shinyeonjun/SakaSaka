# SakaSaka: 코드가 아니라 원래 목적에서 다시 시작

2026-09-17. 기준 main: `5ead4100af9fb3a1ac2499ae1e6a59f6f99bef9c`.

## 원래 하려던 것

사람은 시작과 의도·선호를 제공한다. AI는 프로젝트를 수행하기 위해 무엇이 필요한지 스스로 발견하고, 조사·설계·구현·실행·검증·유지보수를 필요에 따라 한다. 사람이 직무를 호출하거나 다음 작업을 공급하지 않는다. 질문·아이디어·우려는 별도 받은 편지함에 보관하고 언제든 답한다. 실제 실행과 증거는 남는다. 중요한 외부 권한, 자원 한도, 중단권은 사람에게 있다.

이것은 모든 모델이 모든 직무를 이미 완전히 수행한다는 입증이 아니다. 모델의 능력을 가능한 한 덜 잘라내는 환경을 만들고 실제 제품 결과로 검증한다는 연구 가설이다.

## 현재 실사용으로 확인된 것과 확인되지 않은 것

화면에는 `process lifecycle action must reference an active process from the current context`, 반복 실패 1회, 마지막 정상 행동 `workspace.list`가 표시된다. 이것은 개발 목표를 충족한 모습이 아니다. 내부 도구 참조 오류가 사용자에게 프로젝트 전체 중단으로 전달되었다는 것은 확인되지만, 원본 실행 기록 없이 잘못된 ID의 발생 원인까지 확정하지 않는다.

이전 CI 성공은 모의 모델에 대해 정의한 실행 계약이 통과했다는 의미였다. 사용자의 실제 모델이 모호한 의도 하나로 프로젝트를 스스로 맡는다는 가설의 검증 결과가 아니다.

## 수정할 결정

이전의 'Codex는 ModelGateway로 JSON 행동 하나만 반환해야 한다'는 원칙은 철회한다. 권한을 통제해야 한다는 요구가 추론과 실행을 매 파일마다 끊어야 한다는 요구를 뜻하지 않는다.

새 기본 연구 경로는 지속적인 Codex App Server thread와 native agent loop다. SakaSaka는 파일/셸/프로세스 도구를 중복 구현해 매번 지휘하지 않는다. Codex가 실제 작업 환경에서 직접 여러 행동을 하고 결과를 읽으며 오류를 복구한다. SakaSaka는 원문 의도, 지속성, 비동기 사람 통로, 외부 관찰 기록, 자원/권한 경계와 정지/재개를 소유한다.

`native turn 완료`와 `제품 목표 달성`은 다르다. 제품 상태의 판단은 근거와 미해결 사항을 가진 checkpoint이고, 제품 성공 주장은 독립적인 실사용 검증과 구분한다. 같은 일을 무한히 반복하는 대신 가치 있는 다음 행동이 없으면 이유와 다시 깨어날 조건을 보존한다.

## 고정하지 않을 것

PM/CTO/Coder/QA 조직도, PRD→설계→구현 같은 단계, 무조건 수행할 테스트 순서, 아이디어 생성 개수, 모델이 말한 에너지 점수, 세션마다 새로 뽑는 원자적 ActionEnvelope을 필수 실행 구조로 삼지 않는다.

## 고정할 것

- 사용자가 부여한 의도와 경계, 원본 증거를 분리한다.
- 질문 등록 자체는 답변을 기다리는 blocking RPC가 아니다. '질문이 저장됨'을 즉시 반환하고 AI는 독립적인 일을 계속할 수 있다. 미응답을 사람의 답변처럼 꾸미지 않는다.
- 사람이 나중에 답하면 동일 프로젝트/세션으로 전달한다. 재시작해도 사라지지 않는다.
- 내부 도구 오류는 먼저 실행 중인 agent가 읽고 복구할 피드백이다. 정책 위반은 해당 행동을 막고, 보안 경계를 무시하지 않는다.
- 자원 한도·일시 정지·종료는 모델의 자율성과 별개로 실행 환경이 강제한다.
- 현재 capability, 실제 실행된 일, 모델의 보고, 제품 검증을 각각 표시한다.
- 기존 프로젝트/파일/질문/경험은 파괴하지 않는다. 새로운 실행 경로는 명시적으로 선택하며 실패 시 예전 모의 경로로 조용히 fallback하지 않는다.

## 제품 합격 기준

빈 작업 폴더와 모호한 제품 의도 하나에서 출발한다. 사람의 다음 작업 지시 없이 실제 파일을 만들고 실행하고 실패를 복구하고 검증한다. 사람이 답하지 않은 질문이 있어도 독립적인 진행이 가능하다. 뒤늦은 답변은 반영된다. 내부 프로세스 ID를 사람이 맞추지 않는다. 중단/재시작과 자원 제한이 동작한다. '완료'라는 문장, CI 초록, 파일 수가 아니라 실제 사용자 시나리오와 남은 한계로 평가한다.

## 연구 근거

외부 문서는 구현 수단의 근거이지 SakaSaka의 효과를 입증하는 자료가 아니다.

- OpenAI, Unlocking the Codex harness: https://openai.com/index/unlocking-the-codex-harness/ — App Server를 통해 전체 agent loop, 지속 thread, 양방향 이벤트/승인을 재사용한다.
- 공식 App Server 문서: https://developers.openai.com/codex/app-server — thread/start/resume, turn/start/steer/interrupt, dynamic tool의 JSON-RPC 계약. dynamicTools는 실험적 기능이므로 설치된 버전의 스키마로 확인해야 한다.
- 공식 보안 문서: https://developers.openai.com/codex/security — sandbox/approval은 명시적인 실행 정책이며 '자유로운 AI'를 이유로 끄지 않는다.

구현·실험 범위와 검증 결과는 이 문서와 PR에 후속 기록한다. 실제 Codex 인증이 없는 환경의 모의 테스트를 실제 모델 능력 검증이라고 표현하지 않는다.
